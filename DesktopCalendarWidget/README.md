# DesktopCalendarWidget · 桌面日历挂件

面向 Windows 10/11 x64 的桌面月历挂件，使用 .NET 8 WPF 开发，无第三方 NuGet 包依赖。项目托管于 [opentools](https://github.com/372431962/opentools)，专注于日历展示。

## 功能

- 公历月历、上/下月切换、回到今天；双击日期回到本月。
- 简体中文与英文界面，在设置中切换，可立即重启生效。
- 农历月日、闰月及干支年份显示。
- 节假日与调休标记，支持本地编辑和手动联网更新。
- 不标记、每周单休、隔周单休（大小周）三种休息日模式。
- **每日天气**：每个日期显示天气图标与最高/最低温度，悬停显示天气现象、温差与降水概率。
- **中英互译小窗**：自动识别方向、双向互译，可置顶到桌面所有窗口之上。
- **自动检查更新**：启动后与每 12 小时查询一次 GitHub Releases，发现新版可一键下载安装包并拉起安装。
- 无边框透明窗口，支持拖动、位置锁定、置顶和鼠标穿透；日历内容垫一层半透明衬底并给文字加阴影，深浅桌面背景下都保持可读，天气动画叠在衬底之上、桌面依然透出。
- 系统托盘、全局快捷键、可选随 Windows 启动；任务栏不显示程序按钮。
- 单实例运行，重复启动会显示已有挂件。

## 下载与使用

1. 前往 [最新版本下载页](https://github.com/372431962/opentools/releases/latest)，选择 `DesktopCalendarWidget-<版本>-win-x64.msi`。
2. 在 Windows 10/11 x64 上双击 MSI 安装。安装包包含 .NET 运行时，无需另装 .NET SDK。
3. 从桌面或开始菜单的「桌面日历」快捷方式启动，通过挂件右上角「⋯」或托盘菜单打开设置。

安装目录为 `%LocalAppData%\Programs\DesktopCalendarWidget`。可在 Windows「设置 → 应用」中卸载。

托盘右键菜单提供「设置」「翻译」「隐藏挂件 / 显示挂件」「退出」；双击托盘图标切换显示与隐藏。鼠标穿透开启后，仍可通过托盘进入设置。

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl+Alt+C` | 切换鼠标穿透 |
| `Ctrl+Alt+L` | 切换位置锁定（锁定后同时禁止拖动与缩放） |

快捷键可能被其他程序占用。启动时若注册失败，程序会列出失效的快捷键；其中鼠标穿透已开启而 `Ctrl+Alt+C` 不可用时，会自动关闭穿透并说明原因。

## 语言

设置窗口顶部「语言」下拉提供**简体中文**和 **English**，写入 `settings.json` 的 `Language`（`zh-CN` / `en-US`）。缺少该字段的旧配置按中文处理，中文仍是默认语言。

- 界面文案在窗口创建时一次性读取，因此改语言需要重开窗口。点击「保存」后程序会询问是否立即重启；选择稍后则新语言已保存，下次启动生效。
- **英文界面自动隐藏农历和中国节假日文字**，等同于中文界面里关掉这两个开关，对应复选框会禁用并给出说明。排班、着色和大小周推算不受语言影响，仍按节假日数据计算。
- 日期与月份格式随语言变化（`2026年 9月` / `September 2026`），星期表头使用 `日一二三四五六` 或 `Sun Mon …`；表格固定周日开头，不跟随区域设置的每周首日。
- 节假日名称来自数据文件，保持原文（如「国庆节」），不做翻译。
- 天气现象名随界面语言变化（`多云` / `Partly cloudy`），温度单位固定为摄氏度。
- 文案存放在 `Strings.resx`（中性资源 = 简体中文）和 `Strings.en-US.resx`，后者编译为卫星程序集 `en-US\DesktopCalendarWidget.resources.dll`；自包含单文件发布时卫星程序集已打进 exe，安装包无需额外文件。MSI 自身的安装界面仍只有中文。

## 翻译（中英互译）

从挂件「⋯」菜单或托盘菜单打开「翻译」窗口：

- **自动识别方向**：输入中文给出英文，输入英文给出中文，无需手动切换；中英混合时按多数派方向处理，纯数字/符号提示不支持。
- **交互**：停止输入 400ms 自动翻译，`Ctrl+Enter` 立即翻译，`⇄` 把译文换回输入框再翻一次，「复制」一键取走译文。
- **窗口置顶**：右上角图钉开关，开启后该窗口显示在桌面所有软件窗口之上（`WS_EX_TOPMOST`），状态与窗口位置会记住。
- **无标题栏**：不显示系统标题栏，界面更干净。拖动窗口按住顶部方向栏即可，右上角是图钉、交换与关闭（✕）三个按钮；窗口四边仍可拖动缩放，尺寸与位置会记住。
- **紧凑布局**：默认 500×396，方向说明、原文、译文、操作按钮自上而下四段排列，空白处显示占位提示，右下角实时显示字数；缩放与位置会记住。
- 单次最多 5000 字，超出部分丢弃并提示；结果可缓存，重复内容不重复联网。

### 翻译接口

设置的「翻译」区可选接口，按顺序降级，失败自动换下一个：

| 接口 | 说明 |
| --- | --- |
| 自动（推荐） | 依次尝试 MyMemory、Google，最后用离线词典 |
| MyMemory | 免费无需 Key，国内可达，匿名额度约 5000 字符/天，用尽后自动让位 |
| Google | 质量较好，但在中国大陆网络经常不可达 |
| 离线词典 | 完全不联网，内置词表逐词直译 |

- 单个接口超时 5 秒；失败的接口 60 秒内不再重试，避免每次都白等一个超时。
- 「在线失败时用内置词典直译」默认开启。**离线词典是词级直译，句子质量差，只供应急**，结果会标注为“离线词典逐词直译”。
- 内置词典是自建词表（含日历与节假日领域词），以简体中文词 → 英文存放在 `Translate\Data\zh-en-dict.json`，运行时反向表用于英译中；中文按最长匹配切词，英文按空格与标点切词，因此没有分词歧义保障。
- **隐私**：译文由第三方接口生成，输入内容会发送到该服务；界面与设置里都有提示。

## 天气

设置的「天气」区控制日历上的天气显示：

- **开关**：「在日期上显示天气和温度」，关闭后格子上不出现天气行。
- **城市**：按城市名查询（默认「北京」），先用地理编码接口把城市解析成坐标，再拉预报；查不到就换下一个支持城市名的数据源。
- **刷新间隔**：30 / 60 / 180 / 360 分钟，默认 60；也可点「立即更新天气」手动拉取。
- **显示**：格子上是「天气图标 + 最温/低温」（如 `⛅ 26/18°`），悬停显示天气现象、温差与降水概率，例如 `多云 18°C ~ 26°C · 降水 20%`。
- **背景动画**：日历背景按**当天**天气铺一层渐变并播放粒子动画——晴天的暖阳光晕、多云与阴天飘过的云、毛毛雨到暴雨的雨丝（越密越快）、飘落的雪花、雾气横移、雷暴的雨加闪光。天气开关关闭、当天没有数据或现象无法识别时退回普通底色；挂件被隐藏（托盘里收起）时动画停止，不占后台。动画绘制在半透明衬底之上、所有文字之后，与文字阴影配合，不影响日期与文字的可读性。
- 日历格子同时容纳天气、温度、农历与节假日标记：窗口默认 640×820，可拖拽边缘缩放，位置与尺寸都会记住。
- 数据源为 Open-Meteo（首选，一次拿多天），不可用时退回 wttr.in；来源名显示在日历底部图例行。
- 数据缓存在本地，断网时继续用上一次的结果，不会让日历一夜之间全空；这时底部图例行会标注「天气为上次数据」，提示当前不是实时天气。
- **范围限制**：免费接口只提供未来 16 天预报和最近 28 天实况，更远或更早的日期不显示天气，这是接口能力所限。
- **隐私**：天气按城市查询，城市名会发送给第三方天气接口。

## 休息日与隔周单休

在设置的「休息日」区域选择模式：

| 模式 | 规则 |
| --- | --- |
| 不标记 | 周六、周日按普通周末显示，不添加排班「休」标记 |
| 每周单休 | 每周只休所选的周六或周日 |
| 隔周单休（大小周） | 单休周和双休周逐周交替，单休周休所选的一天，双休周休周六、周日 |

配置大小周时，选择单休日，并用「本周是单休周」指定本周状态：勾选表示单休，不勾选表示双休。一周以**周一**为起点；首次设置、切换到隔周单休或修改本周状态时，将界面所示本周周一记为基准。其他显示选项不会重设已有基准。

从基准周向后，按周末调休后的实际休息天数推算：

- 原双休周因周六补班变成单休，下一周改为双休，此后继续交替。
- 原单休周因周末放假变成双休，下一周改为单休，此后继续交替。
- 周中放假或补班不改变周末大小周顺序；周末两天都上班时，保持该周原计划的交替节奏，不把零休误当双休。
- 放假、补班先覆盖当天，再决定后续周次。手动基准周之前仍按原自然周奇偶回推并覆盖当天安排；历史调休不会反过来改变已手动确定的基准。

推算需要对应日期的放假/补班记录。缺少年度数据时，请先使用手动更新或本地编辑补齐。

配色与标记：

- **红色**：不标记模式下的周末，或排班模式下的休息日，以及数据中标为放假的日期。
- **橙色「班」**：数据中标为调休上班的日期，优先于休息日规则。
- **「休」**：排班休息日；有节假日名称时优先显示名称。
- 单休周需要上班的周末日期显示普通颜色，节假日数据另有标记时除外。

节假日显示选项只控制节日名称和「班」文字，不改变当天实际作息、着色或后续大小周顺序。关闭名称显示后，补班日也不会重新标成「休」。

## 节假日数据与手动更新

**当前内置基础数据只有 33 条，不等同于完整年度放假调休安排。** 2025 年数据不完整且缺少调休上班日，2026 年仅包含节日当天。使用前请更新，并按官方公布的放假调休安排核对；内置数据不覆盖未来多年。

在设置中手动触发联网更新，程序会依次请求当前年和下一年的数据。默认接口为：

```text
https://timor.tech/api/holiday/year/{0}
```

- `{0}` 为年份占位符，自定义地址必须保留它，并提供程序可识别的日期、名称及调休字段。
- 节假日数据不会在后台自动联网更新（后台的定时请求只有「自动更新检查」和天气刷新）。接口不可用时继续使用已有本地数据。
- 更新按日期合并：同日记录被替换，接口未返回的旧记录会保留。更新成功也不代表年度数据完整，应核对并修正遗漏或旧记录。
- 下载成功的数据立即保存到本地；更新地址在点击「保存」后写入配置。

设置中的「本地数据编辑」支持**每行一个 JSON 对象**。以下仅演示格式，不代表完整放假安排：

```json
{"Date":"2026-10-01","Name":"国庆节","IsWorkday":false,"IsHoliday":true}
```

日期使用 `yyyy-MM-dd`；调休上班日设置 `IsWorkday: true`、`IsHoliday: false`。编辑后点击「保存本地节假日数据」或「保存」。

## 自动更新检查

程序会查询本仓库 GitHub Releases 的最新版，与自身版本比较。这是**版本更新检查**，与上面「节假日数据更新」是两件事：节假日数据仍然只能手动更新。

- **时机**：启动 8 秒后查一次，之后每 12 小时一次；设置的「更新」区可以关掉自动检查，或随时点「立即检查更新」。
- **不打扰**：后台检查静默进行，断网、接口限流或超时都不弹错误窗，只在手动检查时提示失败。同一个版本选择「不再提示这个版本」后不再弹窗，直到出现更新的版本。
- **发现新版**：弹窗显示版本号与安装包大小，可选 下载 / 稍后 / 不再提示。
- **下载**：安装包（MSI）下载到数据目录的 `updates\` 子目录，先写 `.part` 再改名，中断不会留下半截安装包；每次下载前会清掉上一次留下的安装包。有进度窗，点「取消」或关闭窗口都会中断下载。
- **校验**：下载完成后先比对字节数，再用 Release 附带的 `SHA256SUMS.txt` 校验哈希（该文件缺失时只按大小判断）。校验不通过会删除安装包并提示，不会启动安装。
- **安装**：下载完成后询问是否现在安装。选择安装时启动 `msiexec` 并退出程序，让安装包覆盖正在运行的 exe；选择稍后则安装包留在 `updates\` 目录里，可自行双击。安装为**当前用户**级别，不弹 UAC，也不重启电脑。
- **没有安装包的新版**：Release 若没带 `.msi`，会改为询问是否打开发布页手动下载。
- **隐私**：检查更新只访问 `api.github.com` 的公开发布接口，不发送任何个人数据或日历内容；关掉自动检查后不会再发起这类请求（天气刷新有各自的开关）。

未安装、直接跑 exe 的用法同样可以检查与下载更新，只是装完新版后需要从开始菜单或桌面快捷方式启动，才能用上安装目录里的新版本。

## 数据目录

配置和节假日保存在 `%LocalAppData%\DesktopCalendarWidget`，可通过设置中的「打开数据目录」访问。

| 文件 | 内容 |
| --- | --- |
| `settings.json` | 窗口位置与尺寸、置顶与锁定、休息日配置、翻译与天气配置、更新地址、自动更新开关与上次检查时间等 |
| `holidays.json` | 节假日与调休记录，文件格式为 JSON 数组 |
| `weather.json` | 天气缓存：城市、坐标、拉取时间与逐日天气 |
| `translate-cache.json` | 最近译文缓存，重复内容不重复联网 |
| `updates\` | 更新安装包下载目录，每次下载前清空 |

直接编辑文件前建议退出程序并备份；注意 `holidays.json` 的数组格式与设置编辑框的逐行格式不同。

## 构建与打包

需要 Windows 和 .NET 8 SDK。在包含 `DesktopCalendarWidget.csproj` 的目录执行；若从 opentools 仓库根目录开始，先运行 `cd DesktopCalendarWidget`。

```powershell
dotnet build .\DesktopCalendarWidget.csproj -c Release
dotnet run --project .\DesktopCalendarWidget.csproj
```

版本号只写在 `DesktopCalendarWidget.csproj` 的 `<Version>` 里（当前 **1.5.0**），打包脚本与程序内的「当前版本 v{…}」都取自它。生成 Windows x64 安装包，使用 **WiX 5.0.2**：

```powershell
dotnet tool install --global wix --version 5.0.2
powershell -File .\installer\build-installer.ps1 -DotNet dotnet
```

运行前确保 `dotnet` 和 `wix` 命令可用。脚本先执行自包含单文件发布，再生成 MSI，产物为：

```text
artifacts\DesktopCalendarWidget-1.5.0-win-x64.msi
```

可双击安装，或执行：

```powershell
msiexec /i "artifacts\DesktopCalendarWidget-1.5.0-win-x64.msi"
```

发布新版本时递增 `<Version>`，并把同样的号写成 `v<版本>` 标签；`-Version` 参数只在需要临时覆盖时使用。

回归测试位于仓库根目录的 `tests`，直接链接生产源码，无第三方测试包依赖。从仓库根目录运行：

```powershell
dotnet run --project tests/DesktopCalendarWidget.ScheduleTests -c Release
dotnet run --project tests/DesktopCalendarWidget.TranslateTests -c Release
```

排班测试覆盖休息日推算；翻译、天气与更新测试覆盖语种识别、离线词典切词、各接口的 URL 构造与响应解析、缓存淘汰、降级链、天气编码映射和 Release 解析，全部离线运行，不依赖网络。

### GitHub Release 自动发布

仓库的 `.github/workflows/release.yml` 在推送 `v1.5.0` 这类版本标签时，先校验标签与工程文件里的 `<Version>` 一致，再运行各套回归测试，使用 Windows 构建器生成 MSI 和 `SHA256SUMS.txt`，并创建对应 Release。上传成功后才公开 Release。发布说明取自本目录的 `RELEASE_NOTES.md`，后续发布前应同步更新——程序内的「检查更新」正是读这个仓库的最新 Release，标签不发布就不会提示新版。

工作流也支持手动运行并指定已有标签，便于重试失败的构建。需要仓库启用 GitHub Actions；发布使用工作流自带的 `GITHUB_TOKEN`，不需要把个人令牌保存在源码中。

## 已知限制

- 仅面向 Windows；当前打包脚本生成 x64 安装包。
- 农历依赖 `ChineseLunisolarCalendar`，支持 1901-02-19 至 2101-01-28，超出范围不显示农历。
- 内置节假日数据不完整，公开更新接口的可用性和数据完整性也不作保证。
- 隔周单休以周一为周界，按基准与周末调休顺延，不支持按月指定周次等复杂排班。
- 全局快捷键可能冲突，可使用托盘菜单操作。
- **翻译与天气依赖免费公开接口，无服务承诺**，可能随时失效、限流或被网络环境屏蔽；程序会自动降级，但不保证总有可用来源。
- 翻译首版只做中英互译，其他语种直接提示不支持；离线词典是词级直译，没有分词与语法处理，句子质量差。
- 天气只显示今天前 28 天到后 16 天的日期，超出范围的格子不显示天气；温度为摄氏度。
- **更新检查依赖 GitHub 可访问**，中国大陆网络下 `api.github.com` 可能超时；后台检查失败是静默的，可在设置里手动重试。只比较本仓库的正式 Release，不会安装任何未发布的构建。
- 构建、安装升级和界面交互需在目标 Windows 环境中验证；本说明不将历史本机检查视为全面兼容性保证。
